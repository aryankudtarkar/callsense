# Datasets and evaluation benchmarks

Dataset rights and model rights are separate. Do not bundle datasets into the repository. Save any authorized corpus outside Git, record the source/version and license, and remove or ignore it after the evaluation. A public download is not automatically unrestricted or representative of real calls.

## Recommended evaluation

1. **Software smoke:** Generate synthetic mono PCM WAV bytes in tests. Exercise header validation, 16 kHz checks, byte/duration limits, short tails, exact silence, corrupted input, and error responses. Synthetic tone/silence proves software wiring only; it does not measure emotion recognition.
2. **Real inference integration:** After downloading the pinned model from its official Hugging Face repository, run it through the actual backend with a permitted public speech sample. Assert that the returned class is one of the model's four documented labels and that scores are finite. The test must fail clearly when weights are unavailable; a fake model may support unit tests but can never satisfy this acceptance test.
3. **External model check:** If RAVDESS terms are followed, make a stable speaker-disjoint partition by actor before any tuning. Evaluate only the four mapped categories (`angry`, `happy`, `neutral`, `sad`); report omitted RAVDESS categories and sample counts. Do not train on or tune against the final test actors. Record the exact split manifest, model revision, and preprocessing.
4. **Metrics:** Report accuracy only alongside macro-F1, per-class precision/recall, confusion matrix, class counts, and coverage. Show raw softmax calibration metrics such as Brier score/ECE only with clear definitions and adequate labeled samples. If fitting temperature or an abstention threshold, use development speakers only and report the test result separately. No synthetic or acted-corpus score is a call-performance estimate. [R1, R3, R8]
5. **Domain statement:** RAVDESS uses acted English performances and 24 actors; model training uses IEMOCAP. Neither validates Indian accents, multilingual/Hinglish speech, telephone compression, real distress, informant calls, or investigator outcomes. Don't report subgroup fairness claims from this sample. [R3, R8, R10, R12]

## Leakage and reproducibility

Never randomly split individual clips when a speaker appears across splits. Use actor/group-based splits and save the split manifest. Avoid selecting thresholds on test labels. Avoid cross-fold window leakage if multiple windows come from a single utterance: all windows from one source recording belong to one partition. For MSP-Podcast, the lab warns of speaker overlap between test partitions and unidentified speakers in training; respect its guidance and agreement. [R1, R12]

## No emergency-call benchmark

No dataset in this comparison is an authorized, representative emergency/fraud-call evaluation corpus. Dataset fit, label meaning, access, telephone bandwidth, and real-world consent are unresolved. The project must call its benchmark “controlled external evaluation,” never “law-enforcement validation.”
